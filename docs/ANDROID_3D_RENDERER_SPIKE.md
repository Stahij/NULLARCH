# Android 3D renderer spike

## Goal

Prove that a real-time 3D core can render inside the existing Jarvis launcher on Android 13 / Snapdragon 732G without replacing the chat, local model, updater, or current workspace architecture.

## Chosen first route

Use Google Filament directly from the existing Android Views app. The official Android integration uses Filament.init(), an Android SurfaceView or TextureView, UiHelper, a SwapChain, and a frame callback. Keep all Filament artifacts on the same release.

Initial artifact set to evaluate (all pinned to one version):
- com.google.android.filament:filament-android:1.80.1
- com.google.android.filament:gltfio-android:1.80.1
- com.google.android.filament:filament-utils-android:1.80.1

Do not add these dependencies to the production launcher until a separate minimal compile spike succeeds. Avoid SceneView/Compose migration for the first experiment.

## Implementation sequence

1. Add an isolated FilamentCoreView hosted by a small test activity or debug-only route.
2. Initialize Filament once; create Engine, Renderer, Scene, View, Camera and UiHelper.
3. Render a low-poly sphere with a restrained emissive look and a small point-light setup.
4. Verify SurfaceView attach/detach, rotation, pause/resume, and destruction order.
5. Add glTF loading with gltfio and load assets/3d/jarvis_core.glb generated by the Blender script.
6. Measure frame pacing, CPU/GPU use, memory, thermal behavior and battery on the target Xiaomi.
7. Only after the spike passes, layer the Filament view behind the existing workspace interaction layer. Preserve a Canvas fallback and the existing saved icon positions.

## Device acceptance gates

- Stable launch and exit; no native crash on repeated open/close.
- Correct lifecycle when switching to chat/settings and returning.
- No continuous rendering while the launcher is backgrounded.
- Target 30 FPS minimum under normal scene load, with adaptive quality under thermal pressure.
- No unacceptable increase in memory or temperature during a 10-minute idle/interaction test.
- App icons remain responsive and existing launcher gestures still work.

## Current status

A first compile/lifecycle spike now exists in the Debug variant only:
- `FilamentSpikeActivity` initializes Filament, Engine, Renderer, Scene, View, Camera, Skybox, UiHelper and SwapChain.
- It renders a dark Filament skybox through a SurfaceView and stops its frame loop while paused.
- The debug application uses the `.debug` application ID suffix so it can be installed beside the signed production app.
- The spike is exposed as a separate **Jarvis 3D Test** launcher icon in Debug builds.
- Only `filament-android:1.80.1` is included, via `debugImplementation`; glTF loading and the Blender asset are not included yet.

This is a renderer/lifecycle compile test, not the finished core. The production launcher still uses Canvas and the release variant does not package Filament. Next gate: confirm the Debug build, install the separate debug APK on the target Xiaomi, and test launch/pause/resume/rotation/exit before adding a mesh or glTF loader.

Release policy: pushes to `main` build Debug only. Signed release APKs are published through version tags or an explicit workflow dispatch, preventing experimental renderer commits from silently replacing a published release.
